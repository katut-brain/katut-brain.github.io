まとめ

この日の保存は1件だけで、テーマは「Claude Code に別の AI（Gemini）の CLI を道具として渡すと、どこまで能力が伸びるか」。1つの AI を使いこなすのではなく、複数の AI を役割で組み合わせて自分の作業環境を組み立てる、という問い意識が通奏低音にある。今週は 11/10・11/11・11/16 にも Claude Code・Muse・Grok Bot など AI 環境づくりの保存が続いており、この関心は今週4日続いている＝単発の流行追いではなく「作りたい」軸で育っている関心と読める。

深掘りで読んだ記事では、Gemini CLI を Claude Code のサブエージェントとして定義し、大量の読み込み・分析は無料枠の Gemini に任せ、判断と編集は Claude に残す分担が紹介されていた。建築の文脈に置き換えれば、点群・図面・BIM のような巨大な資料の「読む」工程と、設計判断の「決める」工程を別の AI に割り振る構図に近い。対象日と異なる日付（11/18 0時台）の保存1件を含む。

  • AI を道具として持たせる：Claude Code に別モデルの CLI を渡すことで、コンテキストの広さや費用の制約を別 AI に肩代わりさせるという含意がある。
  • 読む AI と決める AI の分担：大量読み込みと最終判断を分ける設計は、自分の制作フロー（資料調査→設計判断）にもそのまま当てはまるかという問いを立てる。
次に考える問い：自分の制作フローで「大量に読む」工程はどこで、そこを Gemini 側に切り出したら Claude Code に残る判断は何になるか？
